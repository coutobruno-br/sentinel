Built-in Compliance Rules

Five essential rules that cover the most common compliance requirements.

HIGH

no-direct-main

Detects direct pushes to protected branches (main/master). Enforces pull request workflow.

HIGH

pr-review-required

Ensures all merged PRs have at least one approval. Prevents unreviewed code from shipping.

CRITICAL

secrets-scan

Scans for hardcoded secrets, API keys, tokens, and credentials. 20+ patterns detected.

MEDIUM

test-required

Checks if code changes include corresponding tests. Supports multiple languages and frameworks.

LOW

license-check

Verifies repository has a valid OSI-approved license. Essential for open source compliance.

Frequently Asked Questions

What permissions does Sentinel need?

Sentinel only requires read access to your code and metadata, plus write access to create check runs and commit statuses. We never store your source code — only audit metadata and evidence hashes.

Can I use Sentinel with private repositories?

Yes! Sentinel works with both public and private repositories. Your code stays private — we only process webhook events and never clone or store your repository contents.

How long does an audit take?

Most audits complete in under 1 second. Sentinel processes webhook events in real-time, so you get immediate feedback on every push and pull request.

Can I add custom rules?

Yes, on Pro and Enterprise plans. You can write custom rules in JavaScript/TypeScript to enforce organization-specific policies and compliance requirements.

What happens if I exceed my plan limits?

We'll notify you when you're approaching your limit. If you exceed it, audits will pause until the next billing cycle or you upgrade. We'll never charge you unexpectedly.

Is there a trial period?

Yes! Every new installation gets a 14-day trial with Pro features. No credit card required. After the trial, you can continue with the Free plan or upgrade.
